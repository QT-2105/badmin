# Sprint 12.7D Scope

## Objective

Final Finance presentation polish before RC, focused on financial hierarchy, semantic color usage, currency readability, table density, form presentation, filters, empty states and warning/destructive tone discipline.

## In Scope

- Revenue, expense and profit visual hierarchy.
- Positive/negative semantic presentation.
- Currency readability and tabular number alignment.
- Transaction badge tone discipline.
- Transaction table/mobile-card readability.

## Out of Scope

- Revenue formula.
- Expense formula.
- Profit formula.
- Category semantics.
- Session relation.
- Payment status.
- Payment method.
- API.
- Mutation.
- Payload.
- Query keys.
- Sorting/filtering behavior.

## Capability Note

The current Finance UI does not expose paid/unpaid states, payment status, payment method selection, transaction detail, edit or delete actions. Those remain N/A for this sprint and were not added.
