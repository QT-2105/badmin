# Sprint 11.11 — Accessibility Hardening Scope

## Status

COMPLETED

## Goal

Harden accessibility presentation across shared primitives and selected product flows without changing business logic, route behavior, permission logic, data sources, validation, payloads, handlers, mutations, stores, APIs, repositories, services, Prisma, or database schema.

## In Scope

- Heading hierarchy review.
- Landmark and main navigation review.
- Active navigation semantics.
- Form label/helper/error association review.
- Dialog and drawer semantics.
- Table header and mobile table semantics.
- Row action accessibility.
- Accessible icon buttons.
- Keyboard focus, focus-visible, Escape handling, and focus return.
- Status text not relying on color only.
- Reduced motion.
- Touch target review.

## Out of Scope

- Permission logic changes.
- Authorization logic changes.
- Route changes.
- Data/query/mutation changes.
- Runtime scheduling behavior.
- Finance or inventory calculations.
- New ARIA roles that do not match native semantics.
- Replacing business workflows.
