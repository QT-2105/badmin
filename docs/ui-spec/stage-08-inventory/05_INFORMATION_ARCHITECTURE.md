# Inventory Information Architecture

## Priority Order

1. Page title and operational guidance.
2. Report period.
3. Current stock and value metrics.
4. Product catalog.
5. Import/export controls.
6. Movement history.
7. Pagination and feedback.

## Page Header

The header should explain:

- Inventory is stored by pieces.
- Operators can still input import/sale by tubes for speed.
- Every stock-changing action creates a movement.

## Metrics

Metrics should remain:

- Product count.
- Current stock.
- Stock value.
- Play usage cost.
- Shuttlecock sales.
- Total shuttlecock outbound amount.

No new metrics should be added in Stage 08.

## Product Catalog

The product catalog should prioritize:

- Product name and brand.
- Balls per tube.
- Current stock.
- Average cost per piece.
- Average usage price per piece.
- Stock value.
- Sale total.
- Actions.

## Stock Forms

Forms should remain compact and operational:

- Product form collapsible.
- Import/outbound forms hidden behind existing tab-like buttons.
- No drawer conversion unless explicitly approved later.

## Movement History

Movement history should prioritize:

- Movement type.
- Title and note.
- Quantity in pieces.
- Cost per piece.
- Usage price per piece.
- Total amount.
- Created time.
