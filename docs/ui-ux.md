# UI and UX

Version: 2026-08-22

Badmin is a compact operational tool, not a marketing site or generic admin
dashboard. Tablet landscape and smartphone portrait are primary runtime
targets.

## App shell

- Desktop/tablet uses a fixed collapsible sidebar.
- Collapse state persists across navigation.
- Mobile uses compact sticky navigation.
- Navigation visibility follows permissions.
- Touch targets must remain large enough for live operation.

## Runtime

Keep the session top bar and stats compact. Courts and next suggestions share
one large `QUẢN LÝ SÂN` region. Player and match-history lists remain one tap
away and may open full screen.

Show only useful live counts such as total, waiting/prepared, and playing.
Legacy just-finished state may remain visible while old snapshots migrate, but
must not behave as a cooldown or be generated by current match completion.

Mobile stacks courts and suggestions vertically. Tablet should keep all courts,
suggestions, refresh, and player review visible or one tap away. Bound scroll
regions so actions are not hidden by headers or footers.

## Shared interaction rules

- Prefer compact default state for infrequently used forms.
- Use `Mở rộng` and `Thu gọn` consistently.
- Prefer simple numeric inputs over accidental steppers.
- Use user-facing level labels from shared helpers.
- Prefer disabled invalid controls and short actionable errors over repeated
  warning blocks.
- Avoid modal-heavy live workflows and unclear tiny icon-only actions.
- Keep shared primitives only while they have real consumers.

## Operational screens

Dashboard remains an overview. Schedule is review-first for past dates. Session
completion shows required inputs, unpaid/missing-data warnings, temporary profit,
and explicit confirmation.

Finance and inventory keep period filters, compact metrics, collapsible forms,
and horizontally scrollable operational tables where needed. Do not restore
large generic filter stacks or enterprise workflows.

Presentation changes must preserve scheduling, persistence, finance, inventory,
authentication, authorization, and permission behavior.
